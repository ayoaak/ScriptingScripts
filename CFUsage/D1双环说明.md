# D1 双环修改版

基于 [Honye / CF Usage](https://github.com/Honye/scripting-scripts/tree/main/scripts/CF%20Usage)，上游提交 `9bb14126c029eb978756e91f2ceca8d48a7f7543`。原作者与原使用说明保留在本目录。

## 显示方式

- 蓝色外圈：D1 读取行数 `rowsRead` / 读取额度。
- 紫色内圈：D1 写入行数 `rowsWritten` / 写入额度。
- 两个圆环分别计算占比；超过额度时圆环画满，详情百分比仍显示真实值。
- 免费版：每天读取 500 万行、写入 10 万行，UTC 0 点重置。
- 付费版：每账单周期包含读取 250 亿行、写入 5000 万行，沿用账户中设置的账单起始日。
- 数据不可用、旧缓存没有 D1 字段或额度周期已过期时显示“–”，有效的零用量显示 0。

账户列表、账户详情和账户小组件使用双环。单个 Worker 的请求统计及用量提醒沿用原脚本；D1 此次新增的是展示，不新增 D1 通知。锁屏小组件受系统限制，可能显示为单色。

D1 的额度单位是“行”，读取查询次数 `readQueries` 和 Workers `requests` 都不等于读取行数。一个查询可能扫描多行，也可能同时消耗读取和写入额度。

## 安装与配置

打开 `CFUsage.scripting` 并选择 Scripting 导入。显示名称保留为「CF 用量」，更新已有同名脚本前可按需备份。

按原脚本配置 API Token、账户和 Free / Paid。API Token 需要原脚本所述的 `Account Analytics: Read` 与 `Workers Scripts: Read`。导入后在脚本内手动刷新一次，以便获取包含 D1 的新缓存。若 D1 显示“–”，进入账号详情的「诊断」，运行 `D1 rows` 探测并检查接口返回。

多账户小组件：小号和中号最多显示两个条目，大号最多四个，其余显示为 `+N`，为双行用量留出空间。Worker 专用小组件保留原布局。

## 数据来源

通过 GraphQL `d1AnalyticsAdaptiveGroups` 的 `sum { rowsRead rowsWritten }` 聚合整个账户当前额度周期的 D1 数据。查询不请求数据库维度，避免按数据库分组后被结果数量截断。D1 查询失败不会阻止原有 Workers 数据展示；原脚本的 Workers 主查询失败仍使本次快照刷新失败。

- [D1 指标定义](https://developers.cloudflare.com/d1/observability/metrics-analytics/)
- [D1 额度与周期](https://developers.cloudflare.com/d1/platform/pricing/)

## 验证

在工作区执行 `node tools/check-cf.cjs`，检查全部 TS/TSX 语法、本地导入，以及 D1 读写独立计算、免费/付费额度、周期过期、旧缓存、零用量、接口失败和圆环映射。

核心计算和中英文字符串经过 TypeScript 严格类型检查。未连接真实 Cloudflare 账户，也未在 Scripting 真机上运行；最终渲染和实际 API 权限需在设备上验证。
