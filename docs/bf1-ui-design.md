# 战地一插件：原生界面设计

> 本文为 0.1.0 设计记录。当前查询首页与原生动画卡片以 [0.3.0 调整说明](bf1-v0.3.0.md) 和运行源码为准。

阶段：第三步设计定稿，2026-11-07。尚未实现 Scripting 插件或验证真机材质。

## 原生能力与实现边界

Scripting 的正式文档已确认 `glassEffect`、`UIGlass`、`GlassEffectContainer` 和玻璃按钮样式。正式版本采用 Scripting TSX 原生视图；网页布局预览只用于审阅信息层级和操作，不作为原生材质的验收依据。

文档依据：

- [Liquid Glass Effect](https://scriptingapp.github.io/guide/View%20Modifiers/Liquid%20Glass/Liquid%20Glass%20Effect/)：glassEffect、UIGlass.regular()、interactive()、glass / glassProminent 按钮。
- [Glass Effect Transition](https://scriptingapp.github.io/guide/View%20Modifiers/Liquid%20Glass/Glass%20Effect%20Transition/)：相关玻璃控件共用容器和 namespace。

目标环境为支持上述 API 的 Scripting 和 iOS 26+。用户安装版本、真机运行效果尚未核对，不推定最低 Scripting 版本号。若需旧系统兼容，开发时必须先核对组件导出与运行可用性，不能仅靠系统版本判断。无法安全使用玻璃 API 时采用普通原生按钮和系统语义内容底色；不支持的材质属性不传入视图。

## 设计方向

使用克制的系统风格，强调可读战绩和快速切换玩家。玻璃用于导航与操作层，数据内容使用稳定的语义背景。不加入战争海报、伪造头像、雷达评分或未经接口证实的统计。

- 原生玻璃区域：导航操作、玩家切换入口、查询主按钮及必要的工具栏；相关自定义玻璃控件放入同一 GlassEffectContainer，不将整页多层玻璃嵌套。
- 正文区域：系统分组背景和内容底色，清晰显示数值、列表、时间与状态。
- 强调色：系统蓝，仅突出主操作和当前选中项。红色用于错误，暖色用于旧缓存或限流提示，并配文字。
- 圆角随控件和系统形状；搜索/按钮为胶囊轮廓，内容分组建议约 20pt；不强行覆盖原生组件系统尺寸。

## 页面结构

### 玩家首页

原生导航标题“战地一”。下方是带明确标签的玩家 ID 输入框、查询按钮，键盘提交与按钮执行同一动作。输入示例为 konekoroku，不自动请求。

依次展示“常用玩家”和“最近查询”两个原生分组列表。行显示玩家名、可用的上次等级与获取时间、当前选中标识。没有缓存的条目只显示已知信息。常用玩家行提供取消收藏操作；历史行提供移除历史操作，两者不混用。提供可发现的菜单/编辑按钮，不能只依赖滑动手势。

空列表提示“还没有常用玩家，查询后可收藏”和“成功查询的玩家会显示在这里”。不添加假玩家来填满页面。

### 玩家详情

导航栏左侧“玩家”返回入口，右侧收藏和刷新。名称很长时允许标题压缩，完整名称在正文换行；控件不挤压名称。

正文首屏：

1. 玩家名称、Rank 和游玩时长；无真实头像资源时使用中性的系统人物符号。
2. 获取时间；有旧缓存时明确注明“缓存”，请求失败不改时间。
3. 四个核心指标按两列展示：击杀、K/D、KPM、胜率。其余指标放到概览的次级列表。
4. 内容分类使用原生紧凑选择器：概览、武器、载具、对局；“玩家资料”作为概览中的导航行，避免六个标签挤在一行。大字体或窄屏下分类改为菜单选择，不能横向裁切。

分类与刷新都留在当前玩家详情内，不创建虚假的底部全局 Tab Bar。

### 各分类内容

| 内容 | 呈现方式与规则 |
| --- | --- |
| 概览 | 核心四项 + 死亡、命中率、爆头率、最高连杀、最远爆头、技巧、助攻、狗牌、维修、治疗、救援；分组列表显示 |
| 武器 | 从 weapons 分离 WEAPON；列表默认按击杀降序；行显示名称、击杀、KPM，点击进入完整统计；搜索及类别/排序通过紧凑工具栏提供 |
| 载具 | 从 weapons 分离 VEHICLE；显示名称、击杀、摧毁、时长；不套用缺失的命中/爆头字段 |
| 对局 | 按时间倒序，显示地图、模式、时间、击杀/死亡；点击展开或进入单场详情，显示服务器名和单场武器；没有明确赛果时不猜测胜负 |
| 玩家资料 | 名称、ID、曾用名与记录日期；战队为空则显示“暂无战队信息”；反作弊为空显示“暂无可用记录”，不能标记为已证实清白 |

独立兵种、SPM、头像和 BF1 聊天记录均不纳入首版已确认能力。

## 尺寸、深浅色和无障碍

- iPhone 优先，横向边距建议 16pt，正文分组间距 20–24pt；核心指标两列，大字体自动改为一列。
- 使用系统字体语义：大标题/标题、正文、辅助说明；等宽数字用于统计。正文建议 17pt，辅助信息建议 13pt，随 Dynamic Type 缩放。
- 图标按钮有效点击区域至少 44×44pt，收藏和刷新有 VoiceOver 标签及状态；不用颜色独自表示选中、失败或过期。
- 深浅色默认跟随系统。浅色为系统分组浅背景与清晰深色文本，深色为深背景与提升的内容分组底色；正式材质颜色交给原生系统。
- 增大字体时不固定行高，不截断核心值；长武器名、地图名和服务器名换行，详细文字在详情页完整展示。
- 减少动态效果时取消形变与位移动画；减少透明度时保持不透明、清晰的操作和内容层。具体无障碍环境读取 API 需在开发时核对，未确认 API 前不编造调用。
- iPad 使用居中内容宽度或原生分栏，避免拉伸手机指标；首版验收先覆盖 iPhone。

## 状态和文案

| 状态 | 界面行为 |
| --- | --- |
| 首次加载、无缓存 | 显示当前查询名称与进度；不展示虚假数字或上一位玩家的数据 |
| 缓存更新 | 保留该玩家数据，显示“正在更新”；刷新按钮进度状态 |
| 成功 | 更新该玩家数据，显示实际“获取于……”时间 |
| 空 ID | 搜索框下提示“请输入玩家 ID”，不请求 |
| 404 | “未找到该玩家，请检查 ID”；原有收藏保留 |
| 网络失败、有缓存 | “更新失败，正在显示缓存”；允许重试 |
| 网络失败、无缓存 | “暂时无法连接，请稍后重试”；不显示空白统计 |
| 429 | “查询过于频繁，请于……后重试”；冷却时禁用请求，但仍可切换查看缓存 |
| 空分类 | 分别显示“暂无武器记录”“暂无载具记录”“暂无对局记录”等 |
| 非法/缺失数据 | 单项显示“—”；无法安全解析整份响应时保留旧数据并提示失败 |

## 交互验收与后续实现

布局预览支持返回玩家首页、查询演示账号、收藏/取消收藏、分类切换和已知样本内容。它不请求真实接口、不模拟第二位真实玩家、不执行本地存储。

下一阶段将以上结构映射到 Scripting 原生组件，并接入已确定的请求、身份隔离、缓存和存储规则。真机验收需包含深浅色、滚动时的玻璃效果、大字体、减少透明度和减少动态效果；网页预览通过不等于这些项目已通过。
