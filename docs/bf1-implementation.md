# 第四步：查询、本地存储与原生界面实现

实现日期：2026-11-07（Asia/Shanghai）。源码位于 `Battlefield1Stats/`。

## 已完成

- 分离原生运行适配、API、解析模型、存储、玩家控制器和 TSX 页面。
- 实现成功查询后的身份索引与规范名称、收藏上限 50、历史上限 20、每账号独立缓存与获取时间。
- 5 分钟新鲜期、过期先显示旧数据、手动刷新、保存失败提示及重试保存。
- 串行请求、同玩家在途合并、仅保留最新等待请求；切换到 B 后 A 迟到只更新 A 缓存。
- 相同 personaId 的新旧名称合并；缺少 personaId 时采用名称回退，后续获得身份后保留收藏。
- 处理空 ID、400、404、429、服务端失败、网络/20 秒超时、非 JSON 和异常字段。
- 429 尊重有效 Retry-After，否则冷却 60 秒，冷却在私有快照保存，重开不能绕过。
- UI 包括搜索、收藏、历史、当前玩家详情、装备过滤/排序、载具、对局详情和玩家资料。
- 使用系统语义颜色与字体；大辅助字体下指标单列、分类改为菜单；玻璃组件经过能力检查后使用。

## 实现与方案的对应

缓存及收藏不依赖 WebView 或浏览器 localStorage，直接使用当前脚本私有 Storage。一个版本化快照减少多键不同步风险，但不宣称提供数据库事务或同步落盘保证。

非空战队仅展示已解析的名称、标签及当前状态；不猜测队员等未验证字段。反作弊暂只展示状态文字；没有记录时明确标为缺失。

为避免原生运行能力不明时执行不兼容属性，玻璃按钮需要 iOS 26+、UIGlass 和容器导出同时可用；其余情况下用普通原生按钮。该检查仍需目标 App 版本验证。
